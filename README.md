# rust-course

Rust с нуля до движка: 20 модулей, 14 912 строк, **ноль зависимостей**.

Весь курс собран на чистом `std`. Ни `serde`, ни `glam`, ни `anyhow`, ни
`rayon`. Это сделано намеренно, и это главная инженерная мысль проекта:
зависимость скрывает ровно то, ради чего ты сюда пришёл. Когда в курсе
по владению памятью неявно стоит `Arc`, ты не видишь ни счётчиков, ни
временем жизни, ни паники. Здесь всё на голом языке.

## Что внутри

20 модулей, каждый — отдельный бинарник:

```
cargo run --bin module07        # ровно один модуль
cargo run --bin module10 --features hot-reload
```

Модули идут от базы к системам:

| Модули | Тема |
|---|---|
| 01–04 | владение, перемещение, ссылки, времена жизни |
| 05–07 | ошибки, `Result`, обработка паник, `catch_unwind` |
| 08–10 | внутренняя изменяемость, интерьеры, `Rc`/`RefCell`, фичи |
| 11–14 | обобщённые типы, трейты, associated types, обобщённые ассоциации |
| 15–17 | итераторы, `Send`/`Sync`, сериализация своими руками |
| 18–19 | FFI к Vulkan-стилю API, линейная алгебра своими руками |
| 20 | идиомы, clippy, архитектура движка, таблица C++ → Rust |

## Три решения, на которых держится всё остальное

**Каждый модуль — отдельная программа, а не модуль в одном бинарнике.**
Ошибка в модуле 7 не блокирует запуск модуля 8: упавший `todo!()` роняет
ровно один процесс. При обучении это разница между «сегодня разобрался» и
«не могу запустить, потому что вчера не закрыл». Плюс нельзя спрятаться
за `use super::*` — видно ровно то, что знаешь.

**Задание ловится паникой, а не возвратом кода.**
В каждом модуле есть `todo!()`. Харнесс в `src/harness.rs` запускает
задание, ловит панику через `catch_unwind` и ставит оценку. Поэтому в
`[profile.release]` нельзя поставить `panic = "abort"` — аборт уронит
первое же незакрытое задание, и весь модуль перестанет запускаться.
Это осознанное ограничение, и о нём написано в самом профиле.

**Профили подобраны под обучение, а не по умолчанию.**

```toml
[profile.dev]     # opt-level 1: компилируется за секунды, но без дыр в скорости
[profile.release] # opt-level 3: переполнение i32 НЕ паникует, а заворачивается
[profile.test]    # opt-level 2: property-тесты из модуля 16 идут вечность при 0
```

Если в `dev` поставить `opt-level 0`, модули 13 и 16 меряют компилятор,
а не твой код. Это заметно на графиках, поэтому профили явные.

## Сборка

```bash
cargo build --release        # 20 бинарников, ~15 с
cargo run --bin module01     # модуль выполняется
```

Тулчейн закреплён в `rust-toolchain.toml`: `stable-x86_64-pc-windows-gnu`.
MSVC в этом репозитории не собирает.

**Сети не нужно вообще.** Нулевой `Cargo.lock` в смысле зависимостей:
`[dependencies]` пуст.

## Ограничения

- Модули 18 и 19 имитируют API, а не связываются с настоящим Vulkan и glTF.
  Задача там — написать слой абстракции, а не интегрировать драйвер.
- Только Windows/GNU. На других платформах не проверялось.
- Это учебный курс, а не production-библиотека: API не стабилизирован.
